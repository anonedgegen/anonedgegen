<command-name>generate-db-adapter</command-name>

You are generating a `db_adapter.py` file that bridges a SQLite mock database to whatever data model the agent uses internally. Agents may define their data model in many ways — dataclasses, Pydantic models, TypedDicts, plain dicts, or even just the shapes returned by their tool functions. Your job is to **discover** the model from the codebase, then generate the adapter.

## Purpose

The db_adapter is the glue between:
- **Mock System** (SQLite tables with flat rows) — generated by `/generate-mock-system`
- **Agent's internal data representation** — however the agent stores/passes data internally

## Step 1: Discover the Agent's Data Model

Search the agent's codebase to understand what data structures it expects. Look in this order:

### 1a. Look for explicit data model files
```
Grep for: @dataclass|class.*BaseModel|TypedDict|NamedTuple
In: {agent_path}/
```

Common locations:
- `data_model.py`, `models.py`, `types.py`, `schemas.py`
- `src/models/`, `app/models/`

### 1b. If no explicit models exist, infer from tool return types
Read the agent's tool implementations and check:
- What do the tools **return**? (dicts, objects, raw values)
- What do the tools **accept** as input? (typed params, untyped dicts)
- What does the agent's system prompt describe the data as?

### 1c. If the agent uses plain dicts, check for structure hints
- Look at test fixtures, sample data, or seed scripts
- Check API documentation or OpenAPI specs
- Look at how the agent's prompt describes the data

### 1d. Decide the adapter's output format

Based on what you find:

| Agent has... | Adapter should return... |
|---|---|
| Dataclasses/Pydantic models with a top-level DB class | Instance of that DB class |
| Dataclasses but no top-level container | A new `MockDB` dataclass you define in the adapter |
| Only plain dicts / no models | A dict-of-dicts: `{"users": {...}, "orders": {...}}` |
| Tool functions that query in-memory data | Whatever format those functions expect to read from |

## Step 2: Analyze the Mock System Schema

Read `<agent_path>/mock_system/db/schema.sql` and map:
- All tables, columns, types
- Foreign key relationships
- Polymorphic patterns (discriminator columns like `type`, `source`, `status`)

## Step 3: Map Schema to Data Model

For each table, determine:
1. **Which data model class/structure it maps to** (or if it becomes a nested field)
2. **How FK relationships translate** to the data model (nested objects, lists, ID references)
3. **Which columns map to which fields** (names may differ between schema and model)
4. **Polymorphic dispatch** — if a table has rows of different "types" that map to different classes

Create a mapping table:

```
Table: users → Class: User (or dict key "users")
  user_id → user_id (PK, dict key)
  first_name + last_name → name: Name(...) OR just fields
  address1, city, state → address: Address(...) OR flat fields

Table: payment_methods → polymorphic on "source" column
  source="credit_card" → CreditCard class (or {"type": "credit_card", ...})
  source="gift_card" → GiftCard class (or {"type": "gift_card", ...})
```

## Step 4: Generate the Adapter

Create `<agent_path>/mock_system/db_adapter.py`:

### If the agent has explicit model classes:

```python
"""
Adapter to load {DB} from the SQLite mock database.
"""

from {path_to_data_model} import (
    {TopLevelDB},
    {Entity1},
    {Entity2},
    ...
)
from {agent_path}.mock_system.db.db import get_conn


def load_{db_name}_from_mock() -> {TopLevelDB}:
    """Load domain data from the SQLite mock database."""
    with get_conn() as conn:
        # Load each entity, resolve FKs, handle polymorphism
        ...
    return {TopLevelDB}(...)
```

### If the agent uses plain dicts (no model classes):

```python
"""
Adapter to load mock database state as plain dictionaries.
"""

from {agent_path}.mock_system.db.db import get_conn


def load_mock_state() -> dict:
    """
    Load all mock database data as nested dictionaries.
    
    Returns:
        {
            "users": {"user_id_1": {...}, "user_id_2": {...}},
            "orders": {"order_id_1": {...}, ...},
            ...
        }
    """
    with get_conn() as conn:
        state = {}
        
        # Users (with nested payment methods, etc.)
        state["users"] = {}
        for row in conn.execute("SELECT * FROM users").fetchall():
            user_id = row["user_id"]
            user = dict(row)
            # Nest related data
            user["payment_methods"] = conn.execute(
                "SELECT * FROM payment_methods WHERE user_id = ?", (user_id,)
            ).fetchall()
            state["users"][user_id] = user
        
        # ... repeat for other top-level entities
        
        return state
```

### If the agent has models but no top-level container:

```python
"""
Adapter to load mock database into domain objects.
"""

from dataclasses import dataclass, field
from typing import Dict, List
from {path_to_models} import User, Order, Product, ...
from {agent_path}.mock_system.db.db import get_conn


@dataclass
class MockDB:
    """Container for all mock database entities."""
    users: Dict[str, User] = field(default_factory=dict)
    orders: Dict[str, Order] = field(default_factory=dict)
    products: Dict[str, Product] = field(default_factory=dict)


def load_mock_db() -> MockDB:
    """Load all entities from the SQLite mock database."""
    with get_conn() as conn:
        ...
    return MockDB(users=users_dict, orders=orders_dict, products=products_dict)
```

## Key Patterns

### Nested value objects
```python
# Multiple flat columns → single nested object
user = User(
    name=Name(first_name=row["first_name"], last_name=row["last_name"]),
    address=Address(address1=row["address1"], city=row["city"], ...),
)
```

### One-to-many via FK
```python
# Load children for each parent
orders = conn.execute(
    "SELECT * FROM orders WHERE user_id = ?", (user_id,)
).fetchall()
```

### Polymorphic dispatch
```python
# Different class/shape based on discriminator column
if row["source"] == "credit_card":
    pm = CreditCard(brand=row["brand"], last_four=row["last_four"])
elif row["source"] == "gift_card":
    pm = GiftCard(amount=row["amount"])
```

### NULL handling
```python
# Always handle nullable columns
name = row["middle_name"] or ""
amount = row["balance"] or 0
items = json.loads(row["metadata"]) if row["metadata"] else {}
```

## Important Rules

1. **Discover first, generate second** — never assume the agent has clean dataclasses. Comb through the code.
2. **Use `get_conn()` context manager** — from the mock system's `db.db` module
3. **Match the agent's existing interface** — if tools expect `db.users["id"]`, return that shape
4. **Handle NULLs** — SQLite columns may be NULL; always provide defaults
5. **Load in dependency order** — parents before children when nesting
6. **One main function** — expose a single `load_*()` entry point
7. **Import only from the agent's own code and mock_system.db.db** — no external deps

## Step 5: Wire It Up

Update `<agent_path>/mock_system/__init__.py` to export the adapter:

```python
from .db_adapter import load_{name}_from_mock
```

If the agent has a place where it initializes its data (e.g. a `get_db()` function or module-level variable), show the user how to swap it:

```python
# In the agent's tool module or main entry point:
from {agent_path}.mock_system.db_adapter import load_mock_db
db = load_mock_db()
```
